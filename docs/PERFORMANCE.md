# Визуал и частота кадров

Цель отрисовки — **до 240 FPS**. В `project.godot` установлен лимит 240 и отключён V-Sync. Вверху справа показывается фактическая частота. Это лимит, а не обещание 240 на любом компьютере: влияют видеокарта, процессор, разрешение, драйвер и режим запуска. Для оценки запускайте отдельное окно игры, закройте редакторские отладочные окна. Монитор 240 Гц нужен для отображения 240 разных кадров в секунду. При отключённом V-Sync возможны разрывы изображения; включить его обратно можно в Project Settings → Display → Window → Vsync → Vsync Mode.

Физика остаётся **60 Гц**: не ускорены перемещение, выносливость, сутки, AI и окна атак. Для симулируемых хостом персонажей используется интерполяция физических позиций между кадрами. Клиенты сохраняют прежнее сглаживание сетевых снимков без второго слоя интерполяции. Загрузка и смена сцены сбрасывают старые позиции камеры и тела.

Изменения отрисовки:

- Границы/трещины тайлов сохраняются в командах CanvasItem и пересобираются при изменении видимой области, добыче/строительстве и генерации. Один лёгкий слой рисует траву/искрокамень 30 раз/с. Узлов на каждый блок нет.
- Кроны используют собственный атлас из 12 вариантов вместо десятков фигур на каждый кадр каждой кроны. Ветер 60 Гц, падающие деревья обновляются каждый кадр. Звук по-прежнему один общий тихий поток; поиск ближайших деревьев 10 раз/с.
- Небо 30 Гц: градиент — одна текстура, солнце/луна/звёзды/дальний план используют сохранённое игровое время. Освещение 30 Гц, симуляция суток прежняя.
- Слоты инвентаря делят два оформления вместо постоянного создания новых ресурсов. Подсказки управления доступны при наведении на компактную панель статуса; клавиши прежние.

Окружение стало контрастнее: сланцевые плоскости, мох на уступах, многослойная листва, холодный верх неба, тёплый горизонт и силуэты разрушенных пролётов вдали. Дальний план декоративный, не добавляет построек в мир.

## Воспроизводимый замер

Обычный запуск измеряет игру с лимитом 240. Для сравнения изменений нужен замер без лимита, в одинаковом окне/сцене, без одновременно работающих тестов:

```sh
godot --path . --script tools/benchmark_render.gd -- --uncapped --seconds=6 --out=/tmp/world.png
godot --path . --script tools/benchmark_render.gd -- --uncapped --arena --seconds=6
```

Первые 2 с — прогрев. Затем выводится `RENDER_BENCHMARK`: средний FPS по реальному времени, медиана/p95 времени кадра, среднее число вызовов отрисовки, GPU, окно, лимит и частота физики. Скрипт отказывается измерять графику в `--headless`. Как и другие `--script` проверки, обычный профиль не загружается автоматически и автосохранение выключено. Для полностью отдельного профиля задайте XDG_DATA_HOME/XDG_CONFIG_HOME/XDG_CACHE_HOME в Linux.

Первичный сопоставимый замер в облаке, окно 1280×720, Compatibility, Mesa llvmpipe **программный** рендерер, seed72419, неподвижный игрок у спавна,6 с после прогрева: до изменений 52,8 FPS/медиана 18,14 мс/p95 25,78 мс/229 draw calls; после первого прохода 78,3 FPS/12,48 мс/16,60 мс/122 draw calls. Это наблюдение одного прогона на CPU-рендерере, не аппаратный бенчмарк и не гарантия стабильных 240. Окончательные замеры и проверки записаны в HANDOFF.md.

## Источник графики

`assets/canopy.png` и генератор `tools/build_canopy_atlas.py` — оригинальные материалы Emberdepths, **CC0-1.0**: https://creativecommons.org/publicdomain/zero/1.0/ . Чужие изображения не использовались. Pillow нужен только разработчику для повторной генерации, игре он не нужен. Изменённый SVG грунта также нарисован для проекта. Аудио прежнее, источник/лицензия в `assets/audio/README.md`.

Финальный прогон тем же способом: **78,5 FPS**, медиана 12,745 мс, p95 15,837 мс, в среднем124 вызова отрисовки (включая счётчик FPS). Отдельная арена с лимитом 240: 62,7 FPS, медиана 15,673 мс, p95 20,001 мс. Это разные сцены, результат арены нельзя сравнивать с исходным миром как до/после.

Кадры настоящей игры: [поверхность днём](visual-day.png), [ночь](visual-night.png). Число FPS на отдельном кадре — показание интерфейса, для сравнения используйте измерение 6 с скриптом выше.
