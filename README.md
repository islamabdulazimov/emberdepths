# Emberdepths

Оригинальный прототип 2D survival sandbox для ПК, вид сбоку. Godot **4.6.3 Standard**, GDScript, без сторонних библиотек. Рабочее название.

Готовы этапы 1–3: процедурный мир, движение, добыча/строительство, кооператив до четырёх игроков, выпадающие ресурсы, подбор, стопки, инвентарь и панель быстрого доступа.

## Запуск

1. Скачайте ZIP ветки `prototype-stage-1` с GitHub (название ветки историческое, внутри актуальная версия), распакуйте **в новую папку**.
2. В Godot нажмите Import, выберите `project.godot`, затем Import & Edit.
3. Дождитесь импорта и нажмите **F5**. Остановка из редактора — F8.

Мир: 192 × 72 блока по 16 пикселей. Seed меняется у узла World в `scenes/main.tscn` через Inspector → World Seed. Одинаковый seed даёт одинаковый рельеф. В центре ровная стартовая площадка; ниже земля, камень и пещеры.

## Управление

| Клавиша | Действие |
| --- | --- |
| A / D | Движение |
| Space | Прыжок |
| Удержание ЛКМ | Добыча выбранной клетки |
| Удержание ПКМ | Установка блока из выбранного слота |
| 1–9, 0 | Выбор одного из десяти слотов панели |
| Колесо мыши | Предыдущий/следующий слот |
| Esc | Открыть/закрыть инвентарь |
| ЛКМ по слоту панели | Выбрать строительный слот |
| ЛКМ в инвентаре | Выбрать стопку, затем нажать на место назначения |

Инвентарь — 30 слотов, первые 10 повторяют панель. Предел стопки — 99. При переносе одинаковые предметы объединяются до 99 с остатком в исходном слоте, разные — меняются местами. Повторный клик по выбранной стопке отменяет перенос. Разделение стопок, выбрасывание по клавише и перетаскивание мышью пока не реализованы.

Инвентарь **не ставит мир на паузу**, но блокирует добычу и строительство мышью. Ходить можно. Нажатия по интерфейсу не добывают блоки за ним. При вводе IP клавиши движения и слотов не действуют.

## Что проверить в этапе 3

1. Запустите F5. Инвентарь изначально пустой, бесконечного запаса блоков больше нет.
2. Наведите на землю под ногами и удерживайте ЛКМ: дёрн добывается за 0,3 с, земля за 0,35 с, камень за 0,65 с. Смена цели сбрасывает прогресс.
3. Из блока выпадет маленький светящийся предмет с гравитацией и коллизией. Подойдите к нему: в пределах примерно 1,7 блока от центра персонажа он подберётся автоматически. У выпавшего предмета есть задержка подбора 0,2 с. При добыче глубже под ногами нужно спуститься к ресурсу.
4. Проверьте иконку и количество на панели. Ещё один такой же блок пополнит ту же стопку.
5. Выберите заполненный слот цифрой или колесом и поставьте блок ПКМ. Количество уменьшится на один; при нуле слот опустеет. Пустой слот строить не может.
6. Откройте Esc, нажмите на стопку, затем на пустой слот. Переместите её обратно в первые десять слотов и закройте Esc.
7. Попытайтесь построить внутри персонажа, в занятой клетке и за пределами досягаемости: предмет не должен расходоваться.
8. После заполнения инвентаря новые предметы остаются в мире. При освобождении места подбирается только доступное количество; остаток не исчезает.

Зелёная рамка — доступное действие, красная — недоступное; причина указана сверху. Дальность взаимодействия — 5 блоков от позиции персонажа до центра клетки. Постройке нужна соседняя твёрдая клетка либо фоновая стена. Фоновая стена после добычи остаётся, ставить стены будем в этапе 4. Если нажаты обе кнопки, приоритет у ЛКМ. Проверки преград между персонажем и целью пока нет.

## Кооператив

У всех должна быть одна версия проекта. Хост управляет физикой, миром и предметами, его окно должно оставаться открытым.

### Два окна на одном компьютере

1. Запустите два экземпляра игры: Godot → Debug → Customize Run Instances → два экземпляра, затем F5. Альтернатива — второй процесс из терминала: `godot --path ПУТЬ_К_ПРОЕКТУ`.
2. В первом окне нажмите **Создать сервер**.
3. Во втором оставьте IP `127.0.0.1` и нажмите **Подключиться**.
4. Двигайте обоих персонажей, добывайте и собирайте ресурсы. Каждый видит своё содержимое инвентаря. Строительство расходует ресурсы владельца.
5. Подключите поздний экземпляр: он должен получить изменённый мир и лежащие предметы.
6. **Отключиться** возвращает в одиночную игру. У остальных вышедший персонаж исчезает.

### Разные компьютеры в одной сети

- На хосте нажмите **Создать сервер** и узнайте его локальный IPv4 в настройках сети ОС, например `192.168.1.25`.
- Остальные вводят этот IP вместо `127.0.0.1` и нажимают **Подключиться**.
- Если ОС спрашивает разрешение для Godot, разрешите доступ в частной сети. Используется **UDP 24567**. Сеть с изоляцией устройств может блокировать соединение.
- Максимум — хост и три клиента. Через интернет нужны доступный адрес и настройка UDP-порта роутера. Автоматического обхода NAT и списка серверов пока нет.

Хост проверяет личность отправителя, дальность, коллизии, время добычи и интервал строительства. При установке клиент присылает номер слота, а тип блока и остаток хост определяет по своему инвентарю. Подбор и перенос стопок также выполняет хост; клиенты не присылают готовые количества. Поздний вход получает seed, размеры, изменения блоков, выпавшие предметы и свой инвентарь.

**Временные правила выхода без сохранений:** через кнопку выхода игрок переносит свой инвентарь в отдельную одиночную копию мира; у хоста эти вещи удаляются из сетевого инвентаря, повторно не выпадают. При обрыве/закрытии клиента его вещи выпадают в сетевом мире после обнаружения отключения. Повторное подключение — новый персонаж с пустым инвентарём, предметы из одиночной копии не переносятся. После ухода хоста клиенты остаются в отдельных копиях мира; переноса роли хоста нет. Это не сохранение сессии. Не рассчитывайте на сохранность прогресса между запусками до этапа 6.

Предсказания движения пока нет: при большом ping управление запаздывает. Позиции передаются 20 Гц, команды — до 30 Гц и сразу при прыжке. При потере пакетов возможен пропуск прыжка. Изменения мира, предметов и личного инвентаря передаются надёжно. Подсветка и полоска добычи на клиенте предварительные; решение принимает хост.

## Проверки

Из корня проекта:

```sh
godot --headless --editor --path . --quit
godot --headless --path . --script tests/smoke.gd
godot --headless --path . --script tests/items_smoke.gd
python tests/run_network.py
```

Сетевому тесту нужны Python 3, `godot` в PATH и свободный UDP 24567. Он запускает пять отдельных процессов примерно на 13 секунд и возвращает ненулевой код при провале любого процесса или ошибке Godot. В облачной песочнице для сокетов может понадобиться разрешённый запуск вне ограничений локального процесса.

Для обычных проверок в облаке с недоступной домашней папкой:

```sh
mkdir -p /tmp/emberdepths-data /tmp/emberdepths-config /tmp/emberdepths-cache
XDG_DATA_HOME=/tmp/emberdepths-data XDG_CONFIG_HOME=/tmp/emberdepths-config XDG_CACHE_HOME=/tmp/emberdepths-cache godot --headless --path . --script tests/items_smoke.gd
```

Сетевой Python-скрипт сам задаёт временные XDG-каталоги, печатает результаты всех процессов и сохраняет их логи во временной папке `emberdepths-network-*`.

- `tests/smoke.gd`: 19 проверок физики, генерации, ограничений изменения мира и обновления коллизий.
- `tests/items_smoke.gd`: 19 проверок стопок, переноса, выпадения, подбора, расхода, полного инвентаря, частичного подбора и команд интерфейса.
- `tests/run_network.py`: 20 сетевых проверок четырёх участников, серверного движения и редактирования, личного инвентаря, расхода, подбора, переноса, позднего входа и выхода без дублирования вещей.

Headless-проверки не подтверждают внешний вид интерфейса и соединение между разными ПК. Ручная проверка кооператива пользователем отложена.

## Структура

- `scenes/main.tscn`, `scripts/main.gd` — состав сцены, создание игроков, ввод и сетевой интерфейс.
- `scenes/player.tscn`, `scripts/player.gd` — тело персонажа, физика и камера.
- `scripts/world.gd` — генерация, два TileMapLayer, проверки и журнал изменений. Отдельных узлов для блоков нет.
- `scripts/interaction.gd` — выбор клетки, подсветка, добыча и строительные команды.
- `scripts/network.gd` — авторитетный хост, RPC, подключение и снимки состояния.
- `scripts/inventory.gd` — данные инвентаря, стопки и перенос.
- `scripts/item_service.gd` — личные инвентари, выпадение, подбор и расход на стороне хоста/одиночной игры.
- `scripts/drop.gd` — маленький физический предмет; отдельный узел нужен только выпавшим вещам.
- `scripts/inventory_ui.gd` — панель и инвентарь.
- `data/blocks.gd`, `data/items.gd` — отдельные таблицы блоков и предметов со стабильными ID.
- `assets/terrain.png` — оригинальный временный пиксельный атлас.

## Ограничения и следующий этап

Пока нет крафта, инструментов, оружия, факелов, установки фоновых стен, врагов, здоровья, дня/ночи, сохранений, звука и экспортированного исполняемого файла. Временно добывать можно без инструмента даже с пустой панелью. Графика техническая, не финальная. Esc открывает инвентарь, отдельного меню паузы нет. Все изменения мира, выпавшие предметы и инвентари теряются после закрытия игры.

Следующий этап — рецепты в отдельных данных, инструмент, оружие, факел и фоновые стены. Бой и опасность — после этого, затем дисковые сохранения.
