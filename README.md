# Emberdepths

Оригинальный прототип 2D survival sandbox для ПК, вид сбоку. Godot **4.6.3 Standard**, GDScript, без сторонних библиотек. Рабочее название.

Готовы ресурсы персонажа, общий интерфейс боссов, тестовый босс Andrew и этапы 1–6: процедурный мир, движение, добыча/строительство, кооператив до четырёх игроков, выпадающие ресурсы, подбор, стопки, инвентарь, панель быстрого доступа, крафт инструмента/оружия/факелов и строительство фоновых стен, противник, здоровье, сутки, смерть с сундуком/духом и сохранения.

## Запуск

1. Скачайте ZIP ветки `prototype-stage-1` с GitHub (название ветки историческое, внутри актуальная версия), распакуйте **в новую папку**.
2. В Godot нажмите Import, выберите `project.godot`, затем Import & Edit.
3. Дождитесь импорта и нажмите **F5**. Перед остановкой через F8 нажмите в игре «Сохранить»: редактор может завершить процесс принудительно.

Мир: 192 × 72 блока по 16 пикселей. Seed меняется у узла World в `scenes/main.tscn` через Inspector → World Seed. Одинаковый seed даёт одинаковый рельеф. В центре ровная стартовая площадка; ниже земля, камень и пещеры.

## Сохранения: этап 6

Справа от панели быстрого доступа появились кнопки:

- **Сохранить** — записывает текущий мир и персонажей. Внизу появляется статус «Сохранено» со временем.
- **Загрузить** — возвращает мир, вещи и позицию персонажа к последней записанной версии, а не обязательно к спавну. Работает вне сетевой сессии; несохранённые изменения текущего запуска заменяются сохранёнными.
- **Новый** — после подтверждения сохраняет и архивирует предыдущий мир, затем начинает новый с другим seed и пустым инвентарём. Архивы не удаляются.

**Мир автоматически загружается при запуске**, записывается каждые **30 секунд** и при обычном закрытии игрового окна. При ошибке записи закрытие предлагает выбор — остаться в игре или выйти без сохранения. Принудительное завершение, включая F8 редактора, может пропустить запись последних секунд, поэтому перед ним нажмите «Сохранить».

Сохраняются игрок (позиция, текущие и максимальные ОЗ/МП/выносливость, внешний вид, состояние смерти), инвентарь и выбранный слот, seed, добытые и поставленные блоки, фоновые стены, факелы, лежащие ресурсы, сутки, враги, сундуки с содержимым и духи с их радиусом. Сообщения сохранения и загрузки показывают координаты. При вынужденном переносе в безопасную точку статус объясняет причину; при загрузке сохранённой смерти сообщает об ожидаемом возрождении. Камера сразу центрируется на восстановленном персонаже. При возобновлении время не пересчитывается по реальным часам: ночь продолжается с сохранённого момента. Если сохранённый живой персонаж оказался внутри построенного блока, загрузка переносит его на безопасную поверхность у старта.

### Короткая проверка после перезапуска

1. Добудьте блок и поставьте другой в узнаваемом месте. Поставьте стену или факел, запомните количество ресурсов.
2. Нажмите **Сохранить** и дождитесь статуса успешной записи.
3. Закройте игру, снова запустите F5. Проверьте: добытый блок отсутствует, поставленный стоит, предметы и факел восстановлены.
4. В том же запуске измените мир ещё раз и нажмите **Загрузить**: должны вернуться сохранённые изменения.
5. Для сундука: погибните, оставьте его закрытым, сохранитесь и перезапустите. Вещи должны остаться в сундуке. Можно проверить и сохранение уже выпущенного раненого духа.

Ночь пользователь пока не проверял вручную — это остаётся отложенной проверкой; автоматический тест восстановления ночного времени пройден.

### Где находятся файлы

В редакторе Godot откройте **Project → Open User Data Folder**. Это каталог данных игры, отдельный от скачанной папки проекта:

- `saves/world_default.json` — текущий мир стандартного профиля;
- `saves/world_default.json.bak` — предыдущая исправная версия;
- файлы `.archive_*` — сохранённые прежние миры/повреждённые оригиналы;
- `profiles/default.json` — постоянный локальный персонаж и его ключ повторного входа.

Для резервной копии переносите **обе папки**, `saves` и `profiles`, при закрытой игре. Не публикуйте файл профиля. Обновление проекта из ZIP при неизменном имени игры не удаляет эти данные. Загрузка проверяет версию формата и генератора; несовместимый файл не применяется.

Если основной файл повреждён, игра пытается открыть `.bak` и показывает это в статусе. Если оба не читаются, текущий мир не меняется и автозапись блокируется, чтобы не затереть исходники. Можно восстановить копию файлов либо выбрать **Новый**, сохранив повреждённые файлы в архив. Повреждённый файл профиля автоматически не заменяется — нужен его прежний файл из резервной копии.

Один профиль нельзя открыть одновременно в двух окнах для записи. Для второго окна используйте другой профиль, как описано ниже. После аварийного завершения блокировка освобождается при новом запуске. Если игра сообщает о занятом профиле, хотя все её окна закрыты, проверьте каталог `profiles/*.lock`; оставшуюся блокировку можно удалить после закрытия всех процессов игры, не трогая `*.json`.

## Управление

| Клавиша | Действие |
| --- | --- |
| A / D | Движение |
| Space | Прыжок |
| Удержание ЛКМ | Добыча / удар клинком / снятие стены или факела по выбранному предмету |
| Удержание ПКМ | Установка блока, стены или факела из выбранного слота |
| 1–9, 0 | Выбор одного из десяти слотов панели |
| Колесо мыши | Предыдущий/следующий слот |
| Esc | Открыть/закрыть инвентарь и крафт |
| ЛКМ по слоту панели | Выбрать строительный слот |
| ЛКМ в инвентаре | Выбрать стопку, затем нажать на место назначения |

Инвентарь — 30 слотов, первые 10 повторяют панель. Предел стопки материалов — 99; кирка и клинок занимают по одному слоту и не складываются. При переносе одинаковые предметы объединяются до 99 с остатком в исходном слоте, разные — меняются местами. Повторный клик по выбранной стопке отменяет перенос. Разделение стопок, выбрасывание по клавише и перетаскивание мышью пока не реализованы.

Инвентарь **не ставит мир на паузу**, но блокирует добычу и строительство мышью. Ходить можно. Нажатия по интерфейсу не добывают блоки за ним. При вводе IP клавиши движения и слотов не действуют.

## Что проверить в этапе 3

1. Запустите F5. Инвентарь изначально пустой, бесконечного запаса блоков больше нет.
2. Наведите на землю под ногами и удерживайте ЛКМ: дёрн добывается за 0,3 с, земля за 0,35 с, камень за 0,65 с. Смена цели сбрасывает прогресс.
3. Из блока выпадет маленький светящийся предмет с гравитацией и коллизией. Подойдите к нему: в пределах примерно 1,7 блока от центра персонажа он подберётся автоматически. У выпавшего предмета есть задержка подбора 0,2 с. При добыче глубже под ногами нужно спуститься к ресурсу.
4. Проверьте иконку и количество на панели. Ещё один такой же блок пополнит ту же стопку.
5. Выберите заполненный слот цифрой или колесом и поставьте блок ПКМ. Количество уменьшится на один; при нуле слот опустеет. Пустой слот строить не может.
6. Откройте Esc, нажмите на стопку, затем на пустой слот. Переместите её обратно в первые десять слотов и закройте Esc.
7. Попытайтесь построить внутри персонажа, в занятой клетке и за пределами досягаемости: предмет не должен расходоваться.
8. После заполнения инвентаря новые предметы остаются в мире. При освобождении места подбирается только доступное количество; остаток не исчезает.

Зелёная рамка — доступное действие, красная — недоступное; причина указана сверху. Дальность взаимодействия — 5 блоков от позиции персонажа до центра клетки. Постройке нужна соседняя твёрдая клетка либо фоновая стена. Фоновая стена после добычи остаётся; её размещение и снятие описаны ниже. Если нажаты обе кнопки, приоритет у ЛКМ. Проверки преград между персонажем и целью пока нет.

## Крафт и строительство: этап 4

Откройте **Esc**. Справа от инвентаря находятся пять рецептов; кнопки показывают текущий запас и стоимость. Недоступные рецепты серые, причина — во всплывающей подсказке. Верстак пока не нужен. Рецепты временные: земля используется как связующий материал, искрокамень питает свет.

| Результат | Стоимость |
| --- | --- |
| Каменная кирка ×1 | Камень ×4, земля ×2 |
| Каменный клинок ×1 | Камень ×6, земля ×2 |
| Искровой факел ×3 | Искрокамень ×1, камень ×1 |
| Земляная стена ×4 | Земля ×1 |
| Каменная стена ×4 | Камень ×1 |

1. Прокопайте несколько блоков вниз от старта. Земля лежит под дёрном, обычный камень начинается примерно на шестом блоке ниже поверхности. Не забудьте оставить блоки для обратного подъёма.
2. Искрокамень — тёмный блок с янтарными вкраплениями. Гарантированный небольшой запас: **три блока вправо от стартового столбца и три–четыре блока ниже поверхности**. В остальном мире минерал встречается небольшими включениями.
3. Соберите материалы, нажмите Esc и создайте кирку. При необходимости перенесите её в первые десять слотов, закройте инвентарь и выберите её. ЛКМ добывает вдвое быстрее. Без кирки пока тоже можно добывать, но медленнее.
4. Создайте клинок и выберите его. ЛКМ делает удар в сторону мыши с интервалом 0,45 с; блоки при этом не добываются. Клинок наносит 18 урона; обычный пепельник в одиночной игре выдерживает три попадания.
5. Создайте стену, выберите её, поставьте ПКМ рядом с существующей стеной или твёрдыми блоками. Стена — фон, сквозь неё можно ходить. Для снятия стены удерживайте ЛКМ **с выбранной стеной**; передний твёрдый блок сначала надо добыть киркой или с другим выбранным слотом. Тип выбранной стены не обязан совпадать со снимаемой.
6. Создайте факел, выберите его и поставьте ПКМ в пустой клетке на фоне стены либо возле твёрдого блока. Факел не мешает движению. Чтобы снять его, удерживайте ЛКМ с любым выбранным слотом, кроме клинка или стены; подойдёт и пустой слот. Удаление последней опоры возвращает факел выпавшим предметом. Твёрдый блок поверх факела не ставится — сначала снимите его.
7. Спуститесь глубже: окружающий свет постепенно уменьшается, установленные факелы освещают область вокруг себя. Затемнение от глубины теперь совмещается со сменой дня и ночи. Факелы пока горят бессрочно, без расхода топлива после установки; свет не отбрасывает тени от блоков.

Крафт выполняется целиком: при нехватке материалов или места ничего не списывается. Можно использовать слот, освобождающийся после расхода ингредиентов. При частично заполненной стопке учитывается место для всего результата рецепта.

## Опасность и смерть: этап 5

**Одна сложность, без голода и жажды.** У персонажа 100 здоровья. После попадания есть 0,9 с защиты, чтобы контакт не снимал здоровье каждый кадр. Автоматического восстановления здоровья больше нет: оно восстанавливается только лечением через игровую логику; расходников лечения пока нет.

- **День — 180 с, ночь — 60 с.** Сверху показаны здоровье, фаза суток, отсчёт и координаты. Последние 15 секунд дня постепенно темнеют; рассвет тоже плавный.
- Первый пепельник появляется примерно через 40 секунд, вдали от игроков. Днём одновременно до двух, попытка появления каждые 25 с; ночью до шести, каждые 8 с. При начале ночи ближайшая попытка происходит через две секунды. Неудачная попытка из-за занятого/выкопанного места не создаёт противника внутри базы.
- **Пепельник** — наземное существо с 45 здоровья. Днём скорость 34 px/s и удар 14; ночью 65 px/s и удар 22, а радиус преследования больше. Преследует игрока, сталкивается с блоками и перепрыгивает небольшие препятствия. Добыча с него — один искрокамень.
- Клинок бьёт по направлению мыши, с ограничением дальности и угла. Твёрдые блоки закрывают удар. Союзники не получают урона друг от друга. С пустым выбранным слотом можно ударить наведённого близкого противника кулаком: обычному врагу это наносит 6 урона, интервал 0,55 с. Кирка остаётся инструментом добычи.
- При нуле здоровья персонаж погибает. **Весь инвентарь переносится в сундук на месте смерти.** Через 1,8 с персонаж появляется у безопасной точки старта: здоровье полное, инвентарь пустой, короткая защита на 3 с. Временный внешний вид — без верхней одежды и головного убора, в нижнем белье; отдельных предметов одежды/экипировки пока нет.
- Последний сундук отмечается координатами сверху. Сундук не мешает движению; закрыть его твёрдым блоком нельзя. Повторная смерть оставляет новый сундук, старые не удаляются. Сундуки сохраняют исходную позицию, даже если убрать землю под ними.
- Для возврата вещей **удерживайте ЛКМ на сундуке с пустым слотом или инструментом** около 0,6 с, в пределах пяти блоков и без твёрдой преграды. Удар клинком вблизи тоже разбивает сундук. Содержимое выпадает рядом и подбирается как обычные ресурсы. В кооперативе вещи не заблокированы для владельца: подобрать их может любой ближайший участник с местом.
- После разрушения появляется **дух сундука**. Он летает сквозь блоки, но его позиция остаётся в радиусе **10 блоков / 160 px** от исходного места сундука. Перед первой атакой есть 1,2 с на подбор вещей. Дух наносит 12 урона при контакте и умирает ровно от **двух отдельных попаданий**, как клинком, так и кулаком. Сильный первый удар не убивает его мгновенно. Разрушающий сундук взмах не поражает только что появившегося духа.

### Проверка игрового цикла

1. Добудьте камень и землю, создайте клинок, положите его в панель и выберите.
2. Подготовьте факелы и небольшое укрытие из твёрдых блоков. Фоновые стены только фон и сами по себе не останавливают врага.
3. Исследуйте поверхность: противники появляются по обе стороны вдали от персонажа. Проверьте три попадания клинком и добычу искрокамня. При получении урона здоровье уменьшается, короткая защита видна вокруг персонажа.
4. Отойдите и проверьте восстановление зелёной выносливости после задержки; красное здоровье само не восстанавливается. Дождитесь ночи и сравните освещение, преследование и частоту противников.
5. Для проверки смерти дайте врагу добить персонажа. После возрождения сравните текущие координаты с координатами сундука. Разбейте его, подберите вещи, выберите оружие и нанесите духу два удара. Можно отступить за десять блоков от места сундука и восстановиться.
6. Для проверки повторной смерти оставьте первый сундук закрытым и погибните ещё раз: оба должны остаться.

Управление, читаемость противников и фактический баланс нужно оценить вручную. Противники пока появляются только на поверхности; навигация простая, они не добывают блоки и могут застрять у высоких препятствий. Урон от обычного падения ещё не добавлен; выход за нижнюю границу мира считается смертью. Нет расходников лечения, брони и улучшения одежды. Факелы дают свет, но не отпугивают врагов.

## Кооператив

У всех должна быть одна версия проекта. Хост управляет физикой, миром и предметами, его окно должно оставаться открытым.

### Два окна на одном компьютере

1. Первый экземпляр запустите обычным F5, нажмите **Создать сервер**.
2. Второй запустите с другим профилем из терминала:

   ```sh
   godot --path "ПУТЬ_К_ПРОЕКТУ" -- --profile=friend
   ```

   Если `godot` не добавлен в PATH, используйте полный путь к исполняемому файлу Godot. В Windows это путь к `Godot_...exe`. Для третьего/четвёртого окна — `--profile=friend2` / `--profile=friend3`. Имена профилей — латинские буквы, цифры и подчёркивание, до 20 символов.
3. Во втором окне оставьте IP `127.0.0.1` и нажмите **Подключиться**.
4. Двигайте обоих персонажей, добывайте и собирайте ресурсы. Каждый видит свой инвентарь.
5. Нажмите **Отключиться**, затем подключитесь снова тем же профилем: вещи, здоровье и положение в мире хоста должны вернуться.
6. На разных компьютерах обычно достаточно стандартного профиля: их файлы находятся на разных машинах.

### Разные компьютеры в одной сети

- На хосте нажмите **Создать сервер** и узнайте его локальный IPv4 в настройках сети ОС, например `192.168.1.25`.
- Остальные вводят этот IP вместо `127.0.0.1` и нажимают **Подключиться**.
- Если ОС спрашивает разрешение для Godot, разрешите доступ в частной сети. Используется **UDP 24567**. Сеть с изоляцией устройств может блокировать соединение.
- Максимум — хост и три клиента. Через интернет нужны доступный адрес и настройка UDP-порта роутера. Автоматического обхода NAT и списка серверов пока нет.

Хост проверяет личность отправителя, дальность, коллизии, время добычи, интервал строительства, урон, здоровье, смерть и возврат вещей. При использовании клиент присылает номер слота, а тип действия, скорость кирки, задержку удара и остаток хост определяет по своему инвентарю. Крафт, подбор и перенос стопок также выполняет хост; клиенты не присылают готовые количества. Поздний вход получает seed, размеры, изменения блоков и стен, факелы, выпавшие предметы, свой инвентарь, сутки, врагов, здоровье участников и сундуки с содержимым. Содержимое сундуков общее для группы, личные инвентари передаются только владельцам.

**Персонажи и выход:** мир и состояния участников хранит хост. При выходе или обрыве связи вещи остаются в записи персонажа у хоста, не выпадают. Повторный вход с того же локального профиля возвращает его инвентарь, здоровье, положение и выбранный слот даже после перезапуска хоста. Связь с сундуком смерти тоже сохраняется. Клиент передаёт только идентификатор/ключ персонажа, а не готовые вещи или здоровье.

После отключения клиент возвращается в свой **прежний одиночный мир**. Вещи из сетевой игры туда не копируются. Перед подключением одиночный мир сохраняется; повторное подключение продолжает отдельного персонажа в мире хоста. Нельзя играть одним профилем в одной сессии одновременно в двух окнах.

Сохранять сетевой мир может только хост. Загрузку другого сохранения и начало нового мира выполняйте после остановки сервера, затем создайте сервер заново. Уход хоста не передаёт управление миром другому участнику; остальные возвращаются в свои одиночные миры.

Предсказания движения пока нет: при большом ping управление запаздывает. Позиции передаются 20 Гц, команды — до 30 Гц и сразу при прыжке. При потере пакетов возможен пропуск прыжка. Изменения мира, предметов и личного инвентаря передаются надёжно. Подсветка и полоска добычи на клиенте предварительные; решение принимает хост.

```sh

XDG_DATA_HOME=/tmp/emberdepths-data XDG_CONFIG_HOME=/tmp/emberdepths-config XDG_CACHE_HOME=/tmp/emberdepths-cache godot --headless --path . --script tests/items_smoke.gd
```

Сетевой Python-скрипт сам задаёт временные XDG-каталоги, печатает результаты всех процессов и сохраняет их логи во временной папке `emberdepths-network-*`.

## Ограничения и следующий этап

Пока нет звука и экспортированного исполняемого файла. Графика техническая, не финальная. Esc открывает инвентарь и крафт, отдельного меню паузы нет. ## Новые ресурсы и здоровье противников

Сверху слева ОЗ (красный), МП (синий), выносливость (зелёный), с текущим/максимальным значением. Клинок расходует 18, кулак 8 выносливости; максимум 100, восстановление 28/с после задержки 0,8 с. Добыча/ходьба бесплатны. Мана пока только ресурс, без заклинаний. Возрождение восстанавливает все три ресурса.

Максимум ОЗ обычных врагов фиксируется при появлении по числу подключённых игроков, включая ожидающих возрождения: ×1 / ×1,25 / ×1,5 / ×1,75, округление вверх. Уже появившийся враг не меняется при входе/выходе. Для пепельника это 45/57/68/79. Скорость и урон не масштабируются. Правило духа на два попадания сохранено.


Для мобов и боссов используется одна функция `scaled_health` в `data/combat_rules.gd`: `ceil(base_health × (1 + 0.25 × (players − 1)))`. Количество ограничено 1–4. Для базовых 100 ОЗ: **100 / 125 / 150 / 175**. Для Andrew: **360 / 450 / 540 / 630**. Босс фиксирует множитель при начале боя. Подключение/отключение не меняет текущие ОЗ и максимум уже появившихся врагов. Расчёт выполняет хост; при загрузке и репликации повторного умножения нет. Стойкость, урон и скорость от числа игроков не меняются.

## Проверка тестового босса Andrew

1. Импортируйте обновлённую папку проекта и нажмите F5. Управление прежнее. Сверху слева проверьте три полоски: ОЗ 100/100, МП 50/50, выносливость 100/100. Автолечения ОЗ нет, лечебных расходников пока нет.
2. Создайте каменный клинок и победите **трёх пепельников** за текущий запуск; общий счётчик виден под полосками. В кооперативе убийства общие, духи сундуков не считаются.
3. Оставьте рядом участок примерно **5 × 5 пустых клеток** над твёрдым полом. Если места нет, появление откладывается и сообщение объясняет причину. Босс появляется в 5–12 блоках от игрока, без отдельной команды вызова.
4. Andrew показывает позу с поднятыми руками около 2,2 с, затем атакует. Внизу появляются имя, красная полоса ОЗ и отдельная золотая полоса стойкости. Она не связана с выносливостью игрока.
5. Проверяйте предупреждения: апперкот подбрасывает, отскок с переворотом безопасен, вертушка бьёт вокруг. Перед суператакой босс краснеет, фиксирует красную область на земле и прыгает туда. Отойдите от отметки: она не преследует игрока. После атак есть окно восстановления.
6. Пять попаданий клинком снимают 90 стойкости: оглушение длится ровно 2 с. Удары в это время снимают ОЗ, не продлевая оглушение; затем стойкость восстанавливается. Следите за зелёной полоской: при нехватке выносливости новая атака не начинается, уже начатая завершается.
7. Смерть босса или участвующего игрока прекращает бой и убирает интерфейс. В кооперативе смерть любого участвующего игрока завершает общий тестовый бой. Повторный Andrew — после перезапуска игры либо «Новый»; в одном запуске он вызывается один раз.

Andrew — отдельная оригинальная временная пиксельная отрисовка: крупное телосложение, живот, длинные волосы, квадратная челюсть. Художественная проработка и баланс ещё требуют ручной оценки. Наград, парирования и новой прогрессии нет. Мана подготовлена как ресурс/API, заклинаний нет; спринт, перекаты и щиты не добавлены.

**Сохранения:** ресурсы персонажа и зафиксированные максимумы обычных врагов сохраняются, старые файлы получают значения по умолчанию. Сам тестовый бой Andrew и счётчик трёх убийств не сохраняются на диск. Загрузка во время боя завершает его; повторный вызов возможен в новом запуске. Возврат из посещения чужого сервера восстанавливает временное состояние своего мира.

Дополнительные автоматические проверки: ресурсы/масштабирование — 32; общий UI боссов — 7; появление/стойкость Andrew — 17; фазы/прыжок/прерывания — 21; четыре реальных ENet-процесса с поздним входом/выходом/фиксированной целью — 22. Headless-тесты проверяют логику, а внешний вид анимаций, читаемость предупреждений и удобство боя нужно проверить вручную в Godot.


## Обновление анимаций

Персонаж теперь двигает руками и ногами при ходьбе; прыжок и падение имеют разные позы, приземление слегка сжимает рисунок. Клинок движется по ускоренной дуге с последующим возвратом руки. Andrew плавно принимает вступительную позу, приседает перед суперпрыжком, группируется при отскоке, разворачивает корпус при вертушке и опускает руки после удара. Пепельник переносит вес при шагах, дух покачивается целиком.

Для проверки: **F5 → A/D → Space → удар клинком**, затем три пепельника для появления Andrew. Посмотрите подготовку, удар и восстановление, а также оглушение. Управление, длительности боевых фаз, расход ресурсов, урон и коллизии прежние. Анимации меняют только рисунок; красные области по-прежнему показывают игровые зоны урона.

Позы вынесены в `scripts/visuals/player_pose.gd` и `scripts/visuals/andrew_pose.gd`. Это оригинальная временная отрисовка с плавными переходами; финальные покадровые пиксельные спрайты ещё впереди. Проверены реальные кадры OpenGL на виртуальном дисплее и 204 существующие автоматические проверки, включая сетевой бой. Ощущение движения и баланс требуют оценки при игре.
